Tensors: The Foundation

Lesson 1 · AIRobot · LLM Inference at the Metal Level

Everything in an LLM is a tensor. The weights are tensors. The activations are tensors. The KV cache is tensors. There is no escape.

An LLM has exactly one job: transform a sequence of input tokens into a probability distribution over the next token. It does this by applying a series of matrix operations — and every matrix in the system is a tensor.

In AIRobot, the abstract class FloatTensor (src/com/llama4j/FloatTensor.java) defines the interface every tensor must implement. The dot and matmul methods here are the computational atoms that everything else is built from.

What is a tensor in this codebase?

AIRobot's FloatTensor is deliberately simple. It's not a general N-dimensional array library. The documentation says it best:

"Over-simplified, shapeless, float tensor. Not a strict tensor, but rather just a sequence of floats, not required to be backed by memory."

A FloatTensor is just a sequence of floats with an abstract size() and indexed access via getFloat(index) / setFloat(index, value). That's it. Every operation — dot product, matmul, softmax, RMSNorm — is built on top of these three primitives.

The tensor hierarchy

ArrayFloatTensor is the "reference" implementation — all other quantized types implement the same interface with different storage formats.

Different weight formats inherit from FloatTensor, each overriding getFloat and setFloat to decompress on the fly:

  • ArrayFloatTensor — Simple float[] array. Every value takes 4 bytes. Baseline.
  • BF16FloatTensor — Brain-float 16-bit. Same exponent range as float32 (8 bits), truncated mantissa (7 bits). 2 bytes per value.
  • F16FloatTensor — IEEE 754 half-precision. 5-bit exponent (smaller range), 10-bit mantissa. 2 bytes.
  • Q4_0FloatTensor — Block 4-bit. Blocks of 8 values share one float32 scale. 0.5625 bytes per value.
  • Q8_0FloatTensor — Block 8-bit. Blocks of 16 values share one float32 scale. 1.0625 bytes per value.

The key insight: getFloat decompresses, dot stays the same. Every quantized tensor implements dot directly on its compressed representation for efficiency — see Q4_0FloatTensor.dot() which computes the dot product without ever materializing the full float32 vector.

What does a forward pass look like, tensor-wise?

When Llama.forward() runs, here's the tensor flow for one token:

  1. Embed lookup: token_embedding_table.copyTo(token_id × dim, x, 0, dim) — one row copy into the activation buffer x
  2. RMSNorm: rmsnorm(xb, x, weight, dim, eps) — elementwise normalize using root-mean-square
  3. QKV projections: wq.matmul(xb, q, dim, dim) — three matrix multiplies, weights × activation
  4. RoPE: Complex rotation on q and k pairs — elementwise 2D rotation
  5. Attention scores: q.dot(k_offset, keyCache, keyOffset, headSize) / sqrt(headSize) — batched dot products
  6. Softmax: att.softmaxInPlace(...) — normalize scores to [0, 1]
  7. Weighted sum: xb.saxpyInPlace(...) — attention weight × value vector
  8. Output projection: wo.matmul(xb, xb2, dim, dim) — mix head outputs back together
  9. Residual add: x.addInPlace(xb2) — skip connection
  10. FFN: w1·x → silu → × w3·x → w2·result — SwiGLU feed-forward with two matmuls and an elementwise multiply
  11. Final projection: wcls.matmul(x, logits, vocab_size, dim) — map to vocabulary scores

Every bullet is a tensor operation. That's the whole pipeline.

Why this matters

Understanding the tensor layer is understanding the cost model of inference:

  • A matmul from a Q4_0 tensor is memory-bound (4-bit weights, 4× less data to load from RAM)
  • A matmul from an F32 tensor is compute-bound (full precision, no decompression overhead)
  • The dot inner loop is where the CPU spends most of its time — vectorized via jdk.incubator.vector.FloatVector
  • Quantization saves memory but adds decompression overhead per getFloat
Trace it yourself: Open src/com/llama4j/Llama.java:169 — the forward() method. Every call to matmul, dot, softmaxInPlace, copyTo, or saxpyInPlace is a tensor operation. Count them. You'll find exactly 6 matmuls per layer (Q, K, V, O, W1, W3, W2 = 7), plus the final classifier.

Check your understanding

How many unique matmul operations happen per transformer layer in AIRobot's forward pass?

Answer: 7. Three for attention (Q, K, V), one for the output projection (O), and three for the SwiGLU FFN (W1, W3, W2). The RMSNorm and RoPE steps use elementwise operations, not matmuls.

Wait — actually, the final classifier wcls.matmul happens once per token, not per layer. Inside forward(), each layer has: wq·xb, wk·xb, wv·xb (3) + wo·xb (1) + w1·xb, w3·xb, w2·hb (3) = 7 matmuls per layer.
