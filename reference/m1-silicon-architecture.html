M1 Silicon Architecture

Reference — the processors available on your Mac, what each is built for, and how LLM inference maps to each.

Heterogeneous SoC Overview

The Apple M1 packs five kinds of programmable compute into one die:

UnitCoresMemoryPrimitivePeak FP32Programmable via
CPU (Firestorm + Icestorm) 4P + 4E L1 192+128 KB / L2 12+4 MB Scalar + SIMD (NEON) ~200 GFLOPS C / Java / Swift
GPU (Apple 7-8 core) 128 EU / 1024 ALU 8 MB SLC + UMA DRAM SIMT (vector threads per tile) 2.6 TFLOPS Metal (compute + graphics shaders)
ANE (Neural Engine) 16 UMA DRAM Conv / MatMul (INT8 / FP16) 11 TOPS Core ML (private framework)
AMX (Matrix eXtensions) 4 (per P-core cluster) — MatMul outer-product (FP16/INT8) ~1+ TFLOPS Accelerate / BNNS (indirect)
SEP (Secure Enclave) 2 Dedicated SRAM Crypto / AES — iOS/macOS security services

M1 GPU is TBDR (tile-based deferred rendering) — the screen is split into tiles; each tile is processed entirely in on-chip tile memory (many 10× faster than DRAM) before being written out.

Unified Memory Architecture (UMA)

Every processor on the M1 shares the same LPDDR4X-4266 DRAM pool over a 128-bit bus at 68.25 GB/s. There is no copy between CPU and GPU memory — they read the same physical addresses. This is the single most important architectural fact for AI inference on Apple Silicon.

GPU Architecture Detail: TBDR

  1. Tiling: Render target divided into tiles (e.g. 32×32 pixels)
  2. Geometry pass: Primitive visibility determined per tile — invisible fragments discarded before shading
  3. Tile memory: Per-tile on-chip SRAM (bandwidth many × DRAM, latency many × lower)
  4. Shader execution: Fragments processed in lockstep SIMD groups (32 threads = 1 "warp" equivalent)
  5. Writeback: Final tile data written to DRAM

For compute workloads (not graphics), Metal compute shaders bypass the tiling rasterizer and operate directly on threadgroups, but still use tile memory for local storage.

ANE Architecture: What We Know

Apple has published no detailed ANE documentation. Community reverse-engineering (hollance/neural-engine) reveals:

  • 16 independent neural cores, each a systolic array-like matmul/conv engine
  • Operates on FP16 and INT8 (M1; M4 added INT8 performance improvements)
  • Every layer of a Core ML model is profiled: unsupported ops fall back to GPU or CPU
  • Best-case: ~4× faster than GPU for a well-optimized Core ML model
  • Key limitations: no arbitrary elementwise, no gather/scatter, limited softmax support
