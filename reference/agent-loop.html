The Agent Loop

Reference — not a lesson. Quick lookup for the agent control loop in AIRobot.

An agent is an LLM wrapped in a control loop that can act on the world and read back the result. The LLM proposes an action as text; the loop executes it and feeds the result back until the LLM can answer.

The loop

          question
             |
             v
   +--------------------+        no TOOL line
   |  build prompt      |---------------------------> final answer
   |  (question +       |
   |   observations)    |
   +--------------------+
             |
             v
   +--------------------+     TOOL: <cmd>
   |  llm.generate()    |--------------------> validate & run command
   +--------------------+                              |
             ^                                         v
             |                              append "OBSERVATION: ..."
             +-----------------------------------------+
                        repeat (max 5 steps)

Protocol grammar

ElementRule
Tool requestOne line: TOOL: <command> (case-insensitive, anchored to line start)
Allowed commandsdate, ls, pwd, whoami, echo
ObservationAppended to the next prompt as OBSERVATION: <output>
Answer cueOnce observations exist, Final answer: is appended to nudge a small model to stop calling tools
Final answerAny reply with no TOOL: line
Iteration capAt most 5 tool steps before a forced final answer

Protocol regex

(?m)^[ \t]*TOOL:[ \t]*(\S[^\r\n]*)

Anchored to the start of a line so a passing mention ("no TOOL: date needed") is not an action. Case-insensitive; group 1 is the command to validate and run.

Tool contract

The command is split into arguments and executed without a shell via ProcessBuilder(argv). No shell means metacharacters like ;, |, and && cannot introduce a second command, so the allowlist on the first argument is meaningful. Output is capped by a 5-second timeout; stderr is merged into stdout; empty output becomes (no output).

Tiny-model note: the shipped system prompt is deliberately short ("You can run commands. To get the date reply with TOOL: date"). Longer prompts made the 1B model refuse or hallucinate instead of calling the tool. The allowlist lives in code, not the prompt, so a weak prompt cannot widen access.
